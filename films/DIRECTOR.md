# 世界的形状 · 导演守则

**做片的规矩只写在这一页。** 仓库里别的文档只放具体的数值、素材和记录：品牌的标志、颜色、字体见根目录 [`STYLE.md`](../STYLE.md)，角标和声音清单见 [`brand/README.md`](brand/README.md)，每部片的经验见各自的 `LESSONS.md`。它们和这一页说得不一样时，以这一页为准，并把那边改掉。

> 你是这部片的导演。片子没有旁白，观众只靠画面、字和音乐看懂一件事，并且愿意看到最后。

## 目标

**回答一个观众真问过的问题，把背后的机制讲透，让人看完想转给别人。**

标准是"经典"：别人再想到这个问题，会回来找这一部。做不到这个水准的不发。宁可慢，不要平庸；一个题调研下来撑不起好片，就直说，换题。

## 最要紧的五件事

按重要性排。前面的没做到，后面做得再好也救不回来。

1. **问题让人好奇，看到就想知道答案。**
   - 写字楼那部问"空着这么多，为什么还在盖"，高层那部问"高层住宅几十年后会变成贫民窟吗"。
   - 不一定要和观众的日子有关，能满足好奇心就够了（作者 2026-10-31）。
   - 开头那一问要用观众自己的话说出来，不用术语，不先给结论。
2. **一个主角，把账算到底。**
   - 跟着一栋楼、一个家族、一场战役、一个人走，每个数字都落在它身上，观众始终知道"我们在看谁"。
   - 账要算对：漏掉的成本、跨时间的比较、换了口径的数字，都会被观众一眼看穿。
3. **一个反直觉的发现，讲到机制。**
   - 不停在现象（"大家都这样"），要讲清"为什么会这样"：钱怎么流、人怎么选、循环怎么越转越快。
   - 那一个发现要落在全片最强的一拍上：音乐重进、全场安静，或者满屏大字。
4. **一个只属于这部片的世界。**
   - 用题目自己的东西来讲：讲楼就是真实的三维城市，讲游戏就是游戏界面，讲战役就是真实地形上的战线。
   - 全片是一个连续的世界，至少一个别人拍不出来的招牌镜头。
5. **第 0 帧就抓人，之后每一屏都不拖。**
   - 观众只给两三秒。第一帧就是情绪最强的画面，2 秒内让人知道这部片要回答什么。
   - 之后每一句读完就走，每一两拍画面就有变化。

## 硬规则

1. **品牌露出。**
   - 左上角标从第一帧一直留到片尾卡之前：圆形的球加"世界的形状"。
   - 球只用圆形的那颗：[`public/assets/brand/kit/mark-disc.png`](../public/assets/brand/kit/mark-disc.png)。**绝不用带方形底的 `mark-*.png` 方块。**
   - 片尾卡：正中"世界的形状"（带圆形的球），下面一行"看见世界如何运行"，底部一行 MakerJackie。片尾卡前可以放一页信息来源。所有平台统一不放网址（抖音会限制站外导流），不放制作页。
2. **数字是真的。** 每个数字都追得到出处和年份，完整来源写进简介（不带链接）。推算、估算、换算的数字说"约"；预测说清是谁说的；公司自报的、描述性的证据不说成定论。
3. **素材有授权。** 音乐和音效用自己的曲库 <https://music.shapeof.world/>；地图用 OpenStreetMap 或 Natural Earth；照片用公有领域或 CC 授权的；字体用 OFL。
4. **交付规格。** 1920×1080，至少 30 fps；真峰值 ≤ −1 dBTP，响度约 −12 LUFS（在成片 MP4 上量）。
5. **发布文案。** 带 **#vibe知识大赏** 和 **@抖音科技**；热点题再加 **#vibe热点新知计划**。简介里不放网址。


## 流程：四道关

每道关作者点头才往下走。全片最多改三版，三版以后的改进放到下一部。新片放在 `films/<目录名>/`，在自己的 worktree 里做，从最近一部复制做法。剧本、画面和音乐由导演自己做，不交给 DeepSeek 等外部模型。

1. **一页纸**（调研完、写剧本前）。写这几样：
   - 那个最反直觉的发现，和撑住它的证据；
   - 主线一句话、主角是谁、结尾那句话；
   - 标题和封面草图：先写三个标题，挑最想点的那个；
   - 为什么这是这个题目最好的讲法。

   方向错了在这一关挡住，比剧本写完再推翻便宜得多。
2. **纯文字剧本**：屏幕上的每一句字，配一行画面说明，附上数字账本和十二点时钟（见"留住观众"）。请 Gemini 只看文字冷读一次：`opencode run -m opencode-go/gemini-4-argon-contributor "<剧本和要它看的问题>"`。让它扮演两个外行，比如 45 岁家长和 21 岁大学生，专抓三类问题：读不懂的、说过头的、无聊到想划走的。它给的数字和说法，你自己核。
3. **前 30 秒样片**，带声音，确认开头抓得住人、画风立得住。作者说"直接做完"，也只免掉等剧本，样片照样先交，点头再做全片。《一句普通的话》v1 跳过了样片，做完 3 分半才发现开头看不懂、整片像幻灯片。
4. **全片**：交之前自己完整审两三轮，每轮都做三件事：看一遍总览图，核一遍事实，再做一次点映。点映时请 Gemini 扮演 3 到 5 个不同的观众看字和总览图，每人标出第一次想划走的时刻和最喜欢的时刻；先修大家最早一起掉下去的那个点。

发片一周后，用蚁小二查各平台数据（`yxer query content-overviews`），在 `LESSONS.md` 里复盘：这部片做对了什么，走了哪些弯路，播放、转发和评论说明了什么。

## 调研

- **先读懂，再讲故事。** 新题先调研到能用三句话讲给外行听，形成自己的判断，再定故事。故事定了，再按故事去补查。查到的大部分东西不进片子。
- **一手来源优先。** 优先用论文原文、原始数据、官方统计和权威著作。新闻、自媒体、知乎高赞只当线索，里面的数字要追回源头。
- **数字账本。** 每个上屏的数字记一行：数字、原文怎么说、出处、年份、口径，还有它是原值、推算还是换算。账本放在 `private/videos/<片>/`，完整来源写进简介。
- **找反证。** 主动找最强的反对意见，写进故事里。关键结论要有两个独立来源；只有一项研究的，就说"一项研究发现"。
- **找只有我们讲得出的东西。** 自己算的账，自己把两份数据放在一起画，自己在真实地图上复原的过程。只是把别人的结论转述一遍，不够。
- 调研可以派子 agent 并行去搜，但结论和数字由导演自己核。

## 剧本

- **一部片只讲一件事，讲透它。** 一条主线贯穿全片。支线可以多，但每条都要扣回主线，扣不回的就砍。不把各家观点摆成清单。
- **答案分层，一层一个新意思。** 讲完小事一定要放大：从一栋楼到一座城，再到一个国家，最后回到"你"。
- **写给完全外行。** 句子短，说大白话，不用术语；英文公司名后面加一句中文说明。观众对数字不敏感，对自己的日子敏感，所以把数字换成时间、实物和人。
- **字少，信息不能少。** 嫌一屏字多，就把信息拆到更多拍、画成画面，或者把细节放进底部小字，论据不能删。删完一行，把屏幕上的字连起来读一遍，看主语还在不在、前后句接不接得上。
- **话不说过头，示意图也一样。** 示意图的趋势只画到研究撑得住的程度。推论中间缺一步，就补一座有结果的桥。
- **不站情绪立场，不强塞"讲句公道话"，不讲观众早就知道的常识。**
- 学星球研究所的节奏：一路抛问题，结尾往上抬一层。他们靠旁白念，我们靠屏幕上的字，所以句子要更短。少用"不是……而是……""你以为……其实……"这类翻转句式，直接说。
- **比喻等观众需要时再出场。** 先用真实场景把现象演完，讲原理时再引入比喻。
- **结尾回到开头的镜头，落到观众身上，收在一句能截图的话上。** 往上抬分四步：锚住刚讲透的那件事 → 往上问一个更大的问题 → 说明这件事回答了它的哪一部分 → 落回观众能看见、能想、能决定的东西。落句是开放的，画面就停在那一刻，不替观众回答。

## 留住观众：HKRR 和十二点时钟

学自影视飓风公开讲过的 HKRR 和时钟理论（整理见 GitHub `Jamailar/high-retention-video-script`）。只学方法，不抄他们的口头禅和片尾话术。

- **HKRR 四样都要有，而且轮着来：**
  - 快乐（Happiness）：惊讶、爽、松一口气、一个小小的满足；
  - 知识（Knowledge）：机制，一个能带走的发现；
  - 共鸣（Resonance）：观众认出自己的处境、好奇或担心；
  - 节奏（Rhythm）：刺激点在全片怎么分布，加上每句字、每个镜头的快慢。

  连着三拍都是同一种（比如一直在讲知识），就插一拍别的。
- **十二点时钟。** 把全片长度画成一个钟，均分 12 格，2 分 30 秒的片子一格约 12 秒。12、3、6、9 点是大刺激，其余 8 格是小刺激。每一格都要让观众的状态变一下：多懂一点、多一个疑问、情绪动一下，或者眼前一新。
  - 12 点：钩子，为什么现在要看；
  - 3 点：第一个大回报，第一份证据或第一次反转；
  - 6 点：机制，"原来是这样运转的"；
  - 9 点：放大，比观众预想的更大、更和他有关；
  - 结尾：兑现开头的问题，落在一句话上。

  影视飓风统计过他们千万播放的片子：好看的地方均匀分在整个钟面上，不是全堆在开头。
- **剧本阶段就画出这张钟。** 每格写四样：时间、HKRR 角色、观众此刻在想什么、这一格之后他变成什么状态。再给 H、K、R、节奏各打 0 到 5 分，附上理由，任何一项低于 3 分就先改剧本。
- **一个论点的讲法：** 现象 → 一个数字 → 换成能感觉到的东西 → 必要时一个比喻 → 一个看得见的例子。数字一次只给一个，不连着堆。
- **自问自答，加真的"但是"。** 每隔几屏，替观众问出他正要问的那句话，下一屏马上回答。全片至少有一次真的"但是"：一个限制、反例或代价，不是装出来的反转。
- **长片是几段短片串起来的。** 超过两分钟的片子，每一段都要有自己的小钩子和小回报，单独剪出来也能看。只为后面做铺垫的段落，是观众最先离开的地方。

## 画面

- **不做幻灯片。** "一行字配一张图，切到下一张"是最常见的失败。每一刻都要有东西在变，镜头动要有理由。
- **画面本身带信息。** 楼按竣工年份长出来，空置是熄掉的灯，缺的那一块直接空着（五颗星空一颗）。眼睛先看到，不用读字也不用算。抽象示意图（圆环、进度条、流程框）不当主角。
- **要有质感。** 有光、有层次、有细节，画面里要有真内容。线框加图标显得简陋。一部片只用一种画风。
- **一个画面只有一个主角。** 字出现时，压暗其他会动、会亮、有颜色的东西。
- **字是画面的一部分。** 没有固定的字幕位：字可以写在物件上、长在场景里，也可以整屏都是字。字要大，要读得完。
- **不用代码画人。** 手、脸、身体拼出来总会落进恐怖谷。要表现人在用手机，一部手机加一根拇指就够了。
- 出处小字只在必要时上屏，用于预测、推算、公司自报和容易误读的数字，其余进简介。

## 节奏和声音

- **开头。** 第一屏就是钩子，接下来两三屏把赌注抬高，说出具体的后果、人群或规模，不说"这和每个人都有关"这种空话。钩子有几种开法：一个东西加一个怪事实、一个答案反直觉的问题、观众经历过的场景、最极端的情形、一个人的选择。第 0 帧就有东西在动，不从空镜、慢推、黑场或铺垫开始，也不放长片名卡。前 10 秒要跟着拍子变，尽快进入第一个有意思的东西。
- **快是每一屏不拖，不是片子要短。** 一句字停到读完就走，约每秒 5 到 7 个字。片长不设上限，不为时长删论点。
- **情绪要有起伏。** 先让观众代入真实场景，再用加速、累积、对比把情绪推上去，在最高点停住，留一拍安静，然后给答案。至少有一次明显的加速，也有一段能喘口气。
- **跟着音乐走。** 结构跟着音乐段落走，关键动作落在拍子上。只在小节线上剪，不改速度。要省时间，先在和弦循环里找几乎一样的小节整段跳过，不删内容。
- **至少一处真正的安静**，放在转折之前。安静时屏幕上要有东西，比如打出下一段的第一句；黑场加停乐，在短视频里像片子结束了。
- **配乐要么节奏鲜明、明快，要么用《千年之后》。** 不拿几首曲库短循环拼一部片。音效配关键动作，音色和材质要对得上；环境声可有可无。

## 封面和标题

- 封面在手机信息流里被看见：一句大白话直接说题目，不用片子里的句子。配一张专门为封面画的主图。横版 1920×1080、竖版 1080×1440 各一张，顶部是品牌条。缩到手机大小一眼能读懂，才算过。
- 标题不超过 20 个字，和封面说同一件事。标题和封面在一页纸那一关就要有草图，没人想点的题，片子做得再好也没人看。

## 交片前自检

交片前，把自己当成第一次刷到这部片的陌生人，逐条回答。答不上来就回去改。

1. 第 3 秒，我想不想看下去？
2. 能不能用一句话说出这部片回答了什么问题？
3. 看完记住了哪一个画面、哪一个数字？
4. 那个反直觉的发现，是不是落在全片最强的一拍上？钟面上 12、3、6、9 点是不是明显比旁边强？有没有哪一段 15 秒只是在讲道理？
5. 每个数字都在账本里、追得到出处吗？有没有哪句话或哪张图说过了头？
6. 有没有哪一段整段删掉，片子也不会变差？有就删掉。
7. 最后一句，观众会不会截图？会想转给谁？

- 能推广到所有片子的，**改进这一页对应的那一条**，不在后面追加新条。

## 技术坑

- **长片渲染会有个别帧的字变乱码或残影，看起来在闪**（《高层》v9：SVG 字"初代 · 推拉门"画成 ▶▌；v11：HTML 字也一样，标题消失后又闪回、"多出来的房子卖掉"成了乱码）。原因是 Chrome 用 GPU 栅格化网页时偶发出错，和字体、写法无关；短片段复现不出来。做法：用 `--disable-gpu-rasterization` 启动 Chrome（《高层》`tools/chrome.sh`，WebGL 照样走 GPU）；定稿前整片渲两遍，逐帧比对，不一样的帧要查。
- **弹簧/回弹缓动会冲过头**：由进度算出来的数字要截断（`Math.min(1, p)`），否则会闪出错的数。
- **AAC 编码会抬高真峰值**：ffmpeg 自带的 `aac` 能冲过 2.7 dB，还不单调。母带从原始 WAV 做，用 Apple 的 `aac_at` 编码（做法见 `films/ai-impact/tools/tpmaster.py`）。
- **多个会话共用一个仓库**：在自己的 worktree 里干活；不要在主工作区 `git pull --rebase --autostash`，也不要 `git reset`。只提交自己的路径。
- **渲染排队**：Mac 上最多同时跑两个 `remotion render`，开渲前先 `pgrep -fl "remotion render"`。
- **共面会闪**：两个面贴在同一平面（房间盒子贴着楼板、隔墙贴着外墙）会 z-fighting，镜头一动就疯狂闪；几何上留 2 厘米以上的缝。细节（家具、窗框）按 fwidth 抗锯齿；灯光只做有意图的渐变，不要随时间随机开关或用 sin 闪电视。
- **WebGL 截图要等 GPU**：three.js 在 layout effect 里同步渲染完，再调 `gl.finish()`，否则偶尔截到半帧（做法见 `films/tower/src/world/engine.ts`）。
- **Overpass 公共服务器常 502、超时**：大片区的 OSM 建筑改用 Geofabrik 的分省 `.osm.pbf`，用 pyosmium 按范围裁（`films/tower/tools/pbf-nanshan.py`）。
- **WebGL 在 Mac 上要走 Metal**：headless Chrome 加 `--use-angle=metal`，否则会慢好几倍。
- **canvas 上画中文**之前，先用 `document.fonts.load()` 把字体载完。
- **曲库 CDN 拒绝 Python 默认的 User-Agent**（403），脚本下载时带一个 UA；目录里的 `bpm` 不准，以自己测的为准。
